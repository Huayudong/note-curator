# RAG vs 长上下文：文档问答的两条路

## 背景

模型上下文窗口已经足够塞下整本文档，检索增强（RAG）还有必要吗？想验证的是：在同一批文档问答题上，直接长上下文和「检索后只喂相关片段」谁更准、谁更便宜。

## 实验内容概括

- **设置**：500 份内部文档（平均 40 页），200 道带标准答案的问答题；同一模型，两种喂法。
- **方法**：长上下文组整本文档直塞；RAG 组用同一 embedding 模型检索 top-5 片段后喂入。
- **关键数据**：RAG 组答对 83%，长上下文组 79%；RAG 平均每次请求 6k tokens，长上下文组 58k；长上下文组在「跨文档比较」类问题上反超 RAG 约 5 个百分点。（顺带一提，长上下文组的 token 账单也很有教育意义。）

## 结论

单文档事实型问答，RAG 更准也更便宜——准确率差距不大，成本差一个数量级。跨文档综合类问题长上下文占优，因为检索 top-5 会漏掉分散在多处的线索。混合方案（检索粗筛 + 相关文档全文细读）大概率两头都占，待验证。

## 延伸思考

> 整理者延伸，非原文观点。

「跨文档问题长上下文更强」，究竟是上下文变长带来的，还是检索截断丢信息的副作用？如果是后者，把 top-k 调大也许就能抹平差距，不必引入长上下文的高成本——值得补一组对照实验。
