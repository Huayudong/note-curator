# 缓存穿透、击穿与雪崩

## 定义

这三个词说的是同一件事的三种坏法：缓存没扛住请求，数据库替它挨了打。区别只在「为什么没扛住」——查的数据根本不存在，是穿透；数据存在但缓存恰好过期，是击穿；一大片缓存同时失效，是雪崩。

## 核心要点

**穿透**：请求的 key 在缓存和数据库里都不存在（常见于恶意构造的 id）。缓存永远等不到回填，每次都打到数据库。解法是把「不存在」也缓存起来（短 TTL 的空值），或者在入口用布隆过滤器先拦一道。

**击穿**：某个热点 key 过期的瞬间，并发请求同时砸向数据库。解法是加互斥锁，让第一个请求回填缓存、其余等着读；对极端热点干脆不过期，由后台定时刷新。

**雪崩**：大量 key 设了相同或相近的过期时间，同一时刻集体失效。解法是在过期时间上叠加随机抖动，把失效摊开；再配合多级缓存和限流兜底。

三者的防守思路其实是同一句：**别让数据库在缓存缺位时裸奔**——要么让不存在变得可缓存，要么让失效错开，要么让并发有序。

## 延伸思考

> 整理者延伸，非原文观点。

布隆过滤器拦穿透时，误判率与位数组大小、哈希函数个数之间有权衡；在 key 数量未知且持续增长的高基数场景里，它是否还比「空值缓存 + 短 TTL」划算？内存开销和时效性各让一步，暂无定论，待实测。
